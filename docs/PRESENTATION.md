# Часть 1. Текст для слайдов

## Слайд 1 — Титул
**«Объектив» — интеллектуальный мониторинг строительной площадки**
Слоган: **«Работа сделана? Спросите у камеры.»**

## Слайд 2 — Проблема
- **Отчётность ≠ реальность.** Подрядчик закрывает объёмы, которых камера не видела.
- **Срыв сроков замечают поздно** — когда он уже случился.
- **Ручной контроль** дорогой, медленный и субъективный.
- **Споры недоказуемы** — нет объективного подтверждения.

## Слайд 3 — Решение (одной фразой)
Система по камерам определяет, **какие работы реально идут**, сверяет с графиком и отчётом подрядчика и показывает отклонения и риск срыва сроков — **с доказательством кадрами**.

## Слайд 4 — Как это работает
```
Камеры → Нейросеть (17 классов техники) → Дедупликация между камерами
      → Уровень дня 0/1/2 → Сверка: план / отчёт / наблюдение
      → Отклонения + риск + прогноз срока → Дашборд и приложение прораба
```

## Слайд 5 — Наш козырь: принцип честности
> **Система не утверждает, что работа выполнена. Она фиксирует только то, что видела.
> Непроверяемое честно помечается «не проверяется» — а не красится в зелёный.**

Мы даём **обоснованные, адресные и справедливые** предупреждения.

## Слайд 6 — Три независимые оси
| Ось | Что показывает | Пример |
|-----|----------------|--------|
| **Наблюдение** | что видела камера | «Техника стоит» |
| **Отчётность** | что заявил подрядчик | «Закрыто 100 %» |
| **Сроки** | сдвиг и прогноз | «+6 дней к плану» |

**Главный сценарий защиты:** заявлено 100 %, а камера техники не видела → **«ложное завершение»**.

## Слайд 7 — Что видит руководитель
- **Портфель объектов** — сначала самые проблемные; беспроблемные не мешают.
- **План/Факт** по каждой работе и **календарь: день / неделя / месяц**.
- **Переброска бригад**: отставание компенсируется опережением — срок держится, а наверх выходит **слабое звено** (например, поставщик арматуры).
- **Карта, риск, методология** — откуда вердикт и как он посчитан.
- **Рейтинг бригад** — соревнование без «надзирателя».

## Слайд 8 — Фишка: приложение прораба
- **Один тап — одно фото.** Минимум кнопок.
- **Работает без интернета:** фото копятся и досылаются сами, когда появится связь.
- **Фото → нейросеть → оценка руководителя → факт выполненных работ.**
- **Соревнование бригад** на объекте — прозрачно и по-честному.

## Слайд 9 — Технологии
- **CV:** YOLO, **17 классов техники**, дедупликация между камерами (один объект — один).
- **Backend:** FastAPI, JSON API (`/health`, `/upload`, `/works`, `/results`) — готов к интеграции.
- **Frontend:** React + TypeScript, дашборд руководителя и мобильное приложение прораба.

## Слайд 10 — Почему мы выделяемся
1. **Честность вместо иллюзий** — «не проверяется» честнее ложного зелёного.
2. **Доказательства кадрами** — меньше споров, обоснованные удержания.
3. **Офлайн-ферст** — работает там, где связь плохая.
4. **Не нужны идеальные фото** — нейросеть толерантна.
5. **Мотивация, а не надзор** — соревнование бригад.
6. **Готово к внедрению** — понятный API и единая форма данных.

## Слайд 11 — Эффект
- Срыв видят **заранее**, а не постфактум.
- **Меньше ручной работы** и субъективности.
- **Справедливые расчёты**, меньше споров по удержаниям.
- Статус портфеля понятен **за 30 секунд**.

## Слайд 12 — Финал
> **«Объектив» — это не камера, которая следит.
> Это система, которая видит стройку честно — и помогает не сорвать срок, а не искать виноватого.»**

**Ставьте камеры. Дайте нам график. Остальное сделаем мы.**

## Короткая версия для устной защиты (30 секунд)
> «На стройке есть график и камеры, а сверяет их человек — вручную. «Объектив» делает это сам: нейросеть находит технику на кадрах, система привязывает её к работам и показывает, **что реально идёт, где подрядчик заявил лишнее и на сколько сдвинется срок** — с доказательством кадрами. Наш принцип — **честность**: мы показываем только то, что видели, а непроверяемое честно помечаем. Плюс приложение прораба: один тап — фото, работает без связи, и соревнование бригад. Камеры есть у всех — мы даём то, что превращает их в управление стройкой.»

# Часть 2. Документация нашей части

## Что делали мы (бизнес-аналитика и приложение)
1. **Каноническая форма данных** плана/факта (п.6 ТЗ) — единый язык для плана, отчёта и кода.
2. **Правила сверки R1–R8** и статусы (наблюдение / ресурсы / ничего / недостаточно данных / ложное завершение).
3. **Три оси** (наблюдение / отчётность / сроки) и таблица «план-факт».
4. **Приложение прораба**: бизнес-логика (офлайн-ферст, ≤2 тапа, соревнование, факт работ), схема состояний фото, модель данных, экраны.
5. **Eкраны/логика интерфейса руководителя**: портфель по проблемности, выбор проектов, календарь день/неделя/месяц, карта, риск, методология.
6. **Интеграция с API** (по ТЗ бэкенд-разработчика): `/health`, `/upload`, `/works`, `/results`.

## API-контракт (по ТЗ бэкенда)
```
GET  /health   → { "status": "ok" }
POST /upload   → { "status":"ok", "file":"...", "detections":[
                    { "class":"excavator", "confidence":0.92, "bbox":[x,y,w,h] } ] }
GET  /works    → { "works":[ { "id":1, "name":"Земляные работы", "status":"in_progress" } ] }
GET  /results  → { "last_upload":"...", "detections":[...],
                    "works_status":[ { "work_id":1, "detected":true } ] }
```
**bbox:** `[x_центр, y_центр, w, h]` в пикселях (центр бокса + размеры).

## Ключевые принципы (для любого слайда/вопроса)
- Система **фиксирует, а не утверждает**; «не проверяется» — честный статус.
- Оси **не смешиваются**: цвет наблюдения зависит только от камеры.
- **Справедливость:** простои по акту исключаются, претензии — только с доказательством.
- **Офлайн-ферст** и **минимум действий** — под реальную стройку.
