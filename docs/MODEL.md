# Модель данных и логика (MVP)

## 1. Сущности

| Сущность | Назначение | Ключевые поля |
|----------|------------|----------------|
| `Camera` | Камера и её зона | `name`, `zone`, `is_primary_for_zone` |
| `Stage` | Этап календарного плана | `name`, `start_date`, `end_date`, `zone`, `required_equipment`, `min_counts` |
| `Observation` | Наблюдение техники на снимке | `camera_id`, `timestamp`, `equipment_type`, `count`, `confidence`, `image_path`, `world_x/y` |
| `Deviation` | Выявленное отклонение | `stage_name`, `zone`, `type`, `severity`, `message`, `image_path` |

## 2. Классы техники (ТЗ)

`dump_truck` (самосвал), `excavator` (экскаватор), `roller` (каток),
`manipulator_crane` (кран-манипулятор), `concrete_mixer` (бетоносмеситель),
`bulldozer` (бульдозер), `truck` (грузовик), `truck_crane` (автокран).

## 3. Дедупликация между камерами

Одну машину могут видеть несколько камер. Используются два режима:

1. **С привязкой к плану** (есть `world_x/world_y` — гомография):
   детекции одного типа в пределах `DEDUP_DISTANCE` и одного временного окна
   (`DEDUP_WINDOW_MIN`) объединяются в один объект.
2. **Fallback (без калибровки)**: считаем не сумму, а **максимум** детекций
   одного типа в зоне (присутствие). Это исключает двойной счёт камер.

Реализация: `backend/app/cv/dedup.py`.

### Как правильно настроить камеры

- Закрепите за каждой камерой **зону** (поле `Camera.zone`).
- Если камеры перекрываются — назначьте **главную камеру зоны**
  (`is_primary_for_zone = 1`); по перекрытию счёт берётся с главной.
- Для точного счёта откалибруйте камеры и считайте `world_x/world_y` (гомография).

## 4. Правила «этап → техника»

Задаются в двух местах:
- в графике (колонки `required_equipment`, `min_counts`);
- в `data/equipment_rules.json` (единая методика).

Приоритет — данные из графика; файл правил — справочник/дефолт.

## 5. Отклонения

| Тип | Условие | Severity |
|-----|---------|----------|
| `missing_equipment` | требуемой техники нет | medium/high (если нужно ≥2) |
| `undercapacity` | техники меньше плана | medium |
| `unexpected_equipment` | техника не предусмотрена этапом | low |

**Risk score (0–100)**: сумма весов отклонений + штраф за просрочку этапа.

## 6. Условия и ограничения

- Модель обучена на ограниченном/синтетическом наборе; классы — 8 типов из ТЗ.
- Трекинг «поведения» — по серии снимков (присутствие и длительность), без видео.
- Настроены правила для 5 этапов; расширяется без изменения кода (JSON/CSV).
- Для точного счёта между камерами нужна калибровка (гомография); без неё —
  режим «присутствие» (max по зонам).
