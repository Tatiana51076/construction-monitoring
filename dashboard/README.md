# Объектив — дашборд руководителя

Веб-интерфейс руководителя (РП, ПТО, технадзор) для мониторинга строительной площадки:
портфель объектов, план/факт по работам, отклонения с доказательством кадром, риск, методология.
React + TypeScript + Vite + Tailwind.

---

## Как открыть (быстрый старт)

**Разработка:**
```bash
npm install
npm run dev          # http://localhost:5173
```

**Сборка (продакшен):**
```bash
npm run build        # соберёт в dist/
npm run typecheck    # проверка типов
```

Прокси на бэкенд задан в `vite.config.ts` (цель `http://217.18.63.89:8000`), поэтому CORS не нужен.

## Что смотреть на вкладках

| Вкладка | Что показывает |
|---|---|
| **План / Факт** | работы, вердикты («Выполнено / Не обнаружено / Переснять»), фото прораба, перераспределение бригад |
| **Календарь** | день / неделя / месяц, простои по акту |
| **Камеры / CV** | кадры с камер, рамки детекции, загрузка снимка, **фото прораба (живые)**, тех.режим с диагностикой |
| **Методология** | объяснение вердиктов (три оси: наличие / интенсивность / динамика) |
| **Риск** | оценка риска объекта 0–100 |
| **Карта** | зоны площадки на плане |

**Тех.режим** (кнопка с гаечным ключом сверху) → блок «Живые данные · диагностика»:
`/health`, число фото, разбивка по вердиктам, сопоставление нарядов; кнопка «Проверить» перечитывает данные.

## Какие данные живые, а какие демонстрационные

**Живые (с сервера):**
- фото прораба и вердикты — `GET /photos`;
- детекция снимка — `POST /upload`;
- `GET /health`, `GET /api/foreman/objects`, `GET /api/foreman/leaderboard`.

**Демонстрационные (зашиты в `src/projects.ts`):**
- объекты, расписание, кадры с камер, риск, методология, календарь событий.

Если сервер недоступен, дашборд автоматически переключается в демо-режим (не падает).

## Модель данных

- **Классы техники (17):** `dump_truck, excavator, motor_grader, roller, crane_manipulator,
  gazelle, forklift_standard, bucket_loader_big, mixer, tanker, bulldozer, cleaning_equipment,
  truck, trailer, forklift_giraffe, bucket_loader_standard, autocran`.
- **Работы и ожидаемая техника** — `src/expected_equipment.json` (единый источник):
  - Бетонирование → `mixer, crane_manipulator, autocran`;
  - Армирование → `bucket_loader_standard, dump_truck`;
  - Котлован → `excavator, dump_truck (×2), bucket_loader_standard`;
  - и др. (Земляные, Монолит, Каркас, Фундамент, Дорожные, Отделка, Благоустройство).
- **Фото (`GET /photos`):**
  ```json
  { "file": "...", "image_url": "/uploads/...", "work": "Бетонирование", "zone": "Секция C",
    "detections": [ {"class":"Mixer","confidence":0.81,"bbox":[52.57,53.31,105.15,56.47]} ],
    "works_status": [ {"work":"Бетонирование","status":"confirmed","found":["mixer"]} ] }
  ```
  `bbox = [x_центр, y_центр, ширина, высота]` в пикселях.
- **Статусы вердикта:** `confirmed` → «Выполнено», `not_confirmed` → «Не обнаружено»,
  `review` → «Переснять», `unsure` → «Не проверяется».

## Условия и ограничения

- Вердикт берётся от сервера (`works_status.status`); если сервер вернул `unsure` — дашборд считает сам из детекций.
- Точность распознавания зависит от модели (YOLO, 17 классов).
- Работает через прокси Vite; продакшен — статическая сборка (`npm run build`).
- Работы без видимых признаков помечаются «не проверяется».
- 17 классов техники — расширенный перечень (обязательных по ТЗ — 8).

## Структура кода

```
index.html, vite.config.ts, tailwind.config.js, package.json …
public/                 — фото зон (camera-zone-*.webp)
src/
  main.tsx              — точка входа
  App.tsx               — каркас, hash-роутинг (#/проект/вкладка), живые данные
  projects.ts           — демо-данные (объекты, работы, зоны, кадры, события)
  data.ts               — 17 классов техники, разбор ответа API
  expected_equipment.ts / .json — таблица «работа → техника» + расчёт вердикта
  liveData.ts           — загрузка /photos и обновление работ
  components/           — компоненты (WorkCard, CalendarView, CameraDetectionView, …)
```

## Как запустить (пошагово)

1. Установить Node.js 18+.
2. Перейти в папку проекта, выполнить `npm install`.
3. `npm run dev` → открыть `http://localhost:5173`.
4. Для живых данных нужен запущенный бэкенд (адрес — в `vite.config.ts`).
